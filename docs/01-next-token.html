Chapter 1

Guess the next character

How can a file full of numbers write a sentence?

A language model does exactly one thing. You hand it some text, and it hands back a list of probabilities: one for every symbol that could come next. That is all. It does not write, it does not answer, it does not chat.

Writing is a loop built around that one ability: ask for the probabilities, roll weighted dice to pick a symbol, glue it onto the text, ask again. Every system in this course, from the toy on the home page to the assistant on your phone, is that loop. The whole difficulty is hidden in one place: how do you compute good probabilities?

So start with the simplest answer anyone could give.

Just count

Take a million characters of Shakespeare. For every character, tally what came right after it. After q you will almost always find u. After a space, often t. Turn the tallies into fractions and you have a language model. It fits in a small table.

One character of context is not much. So let the table look further back: the last two characters, the last three. The number of characters it looks back is called the order.

A language model made of tallies

Try this. Press Write at order 0, then 1, then 3, then 5. The text goes from letter soup to something that looks like English. Then read the two numbers under the slider at order 5.

At order 5 the text looks impressive. Look at the readout, though: most of the contexts in the table were seen only once or twice. When a context was seen once, there is only one continuation on record, and the model has no choice but to replay the book. It is not writing. It is quoting.

A ruler for language models

We need a way to tell a good model from a quoting machine. Here is the test that all of machine learning for language rests on: show the model real text it has never seen, and at each position ask how much probability it gave to the character that actually came next.

If it gave probability p, we score its surprise as −log p. A confident correct guess (p near 1) costs almost nothing. A guess of p = 0.01 costs 4.6. The average surprise over a text is called the loss, or cross-entropy. Lower is better.

loss = − average of log p(the character that actually came next)

Why the logarithm? Because probabilities of a sequence multiply, and logs turn products into sums. The total surprise of a text is then the sum of the surprises of its characters, which is what you want from a ruler. A model that guesses uniformly among our 65 characters scores log 65 ≈ 4.17 at every position. That is the number to beat.

Where is the model surprised?

Try this. Each character is shaded by its surprise: darker means the model did not see it coming. Switch between text the model counted and text it never saw, at order 1 and then at order 5.

At order 5 the gap is plain. On text it has counted, the model is almost never surprised. On new text from the same play it stumbles constantly, because most five-character contexts it meets were never in its table.

The loss on counted text falls forever. The loss on unseen text falls, bottoms out at order 4, then climbs. More context should help, and it does, until the table is so sparse that most lookups come back empty. The number of possible contexts multiplies by 65 with every extra character. The amount of text does not.

This is the wall. A table treats every context as unrelated to every other. It has seen the king a hundred times and the duke a hundred times, and that tells it nothing about the earl. To get past the wall we need a model that treats similar contexts similarly. Instead of looking the answer up, it must compute it, with a formula whose adjustable numbers are tuned on the data. The rest of part one builds that formula.

Build it

def fit(order):
    """counts[context][next_char] = how often next_char followed context."""
    counts = defaultdict(Counter)
    for i in range(order, len(train)):
        counts[train[i - order:i]][train[i]] += 1
    return counts

def prob(counts, context, ch, alpha=0.01):
    """P(ch | context), with a tiny bit of probability reserved for the unseen."""
    c = counts.get(context, {})
    return (c.get(ch, 0) + alpha) / (sum(c.values()) + alpha * V)

def loss(counts, order, s):
    """Cross-entropy: the average surprise, -log p(what actually came next)."""
    return -sum(math.log(prob(counts, s[i - order:i], s[i])) for i in range(order, len(s))) / (len(s) - order)

From code/ch01_ngram.py. The whole model is a dictionary of counters.

def sample(counts, order, n=120, seed=0):
    rnd = random.Random(seed)
    out = train[:order]                        # seed with the first few characters
    for _ in range(n):
        c = counts.get(out[len(out) - order:], None)
        if not c:                              # never saw this context: the table has no answer
            out += rnd.choice(train)
            continue
        chars, weights = zip(*c.items())
        out += rnd.choices(chars, weights)[0]  # roll the weighted dice
    return out[order:]

Writing is the loop: look up, roll, append.

What this chapter glossed over

The ruler measures imitation. A low loss means the model predicts text that resembles its training text. It says nothing about whether the text is true, kind or useful. Keep this in mind when the models get large: the ruler does not change.

Units. Losses here use the natural logarithm, so the unit is the nat. You will also meet bits (log base 2) and perplexity, which is eloss: the number of equally likely options the model is effectively hesitating between. A loss of 1.68 is a perplexity of 5.4 characters.

Unseen is not impossible. A raw count of zero would mean probability zero and infinite surprise. The code adds a tiny constant to every count so that nothing is ever ruled out completely.

Check yourself

Why does uniform guessing cost exactly log 65?

Each of the 65 characters gets probability 1/65, so the surprise at every position is −log(1/65) = log 65 ≈ 4.17, whatever the text says.

The order-6 model scores 0.90 on counted text and 2.24 on unseen text. Which number describes the model?

The second. The first measures memory. Only text the model has not seen tells you how it will behave on anything new, which is the only situation you will ever use it in.

A real model reads 100,000 tokens of context. Could a count table do that?

No. Even with our tiny 65-symbol alphabet, the table for 6 characters of context already has 75 billion possible rows. The idea has to change, not scale.

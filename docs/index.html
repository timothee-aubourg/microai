A language model you can hold in your head

The text below is being written right now, on your device, by a model with 345,504 numbers in it. It was trained from scratch on Shakespeare with the code in this repository: numpy, no deep-learning library.

It is bad Shakespeare. But it is the same kind of machine as the multi-gigabyte model you can run on a laptop, and the same kind as the assistants you use every day. Only the numbers are fewer. This course takes that machine apart and puts it back together, one idea per chapter, until you can build each piece yourself and then run a real model on your own computer.

How each chapter works

Every chapter follows the same three moves.

  • Why. It opens with a real problem. An idea only makes sense once you have felt what goes wrong without it.
  • See. You get an experiment to play with. Most of them run on the actual trained model, so what you see is measured, not drawn.
  • Build. You read the few lines of code that implement the idea. The snippets are copied from the files in code/ by a script, so they are the code that runs.

Three colours mean the same thing on every page: blue for values flowing forward through the model, raspberry for gradients and error flowing backward, amber for probabilities.

The path

Text goes in on the left; a guess about the next token comes out on the right. Chapters 1 to 6 build that pipeline. Chapters 7 to 9 make it learn, write and shrink. Chapters 10 to 12 turn it into a system on your machine. Chapters 13 and 14 make that system dependable. Chapters 15 to 17 open up the harness that turns a model into an agent. Chapters 18 and 19 go down to the hardware and then put every part together in one system you train yourself. Chapters 20 and 21 show two ideas that full-size models add: experts, and room to think. Chapters 22 and 23 fit the model to the machine: where the weights live, and how small a working model can be made. Chapter 24 covers what comes after pre-training: how examples and rewards turn a model that imitates text into one that behaves. Chapter 25 leaves the weights alone and improves the answers at the moment of asking. Chapters 26 and 27 are about speed and scale: writing several tokens per pass, and serving many people with one model. Chapters 28 and 29 are about small models that work for a large one: a classifier that guards it, and a student that learns from it. Chapters 30 and 31 look inside current models: how they now mark position, and how a picture gets in. Chapters 32 to 34 take the agent further: it hands parts of a job to helpers, learns from its own answers, and is then rebuilt whole with every part added since chapter 19. Chapters 35 and 36 ask whether that system is safe to release: it is attacked, repaired and attacked again, then released in steps and watched. Chapters 37 and 38 plug things into the agent: tools it was never trained on, offered by other programs, and a catalogue too large for its context, loaded a piece at a time.

                                Run the code yourself

                                The only dependency is numpy. Training takes roughly a quarter of an hour on a laptop CPU.

                                git clone <your fork of this repo> && cd microai
pip install numpy
python code/ch01_ngram.py      # every chapter has a script like this
python code/train.py           # trains the model you see on this page
python code/ch08_sample.py --prompt "ROMEO:"

                                Each script prints what it is doing. Read it top to bottom; none is longer than a few screens.

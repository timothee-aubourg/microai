Chapter 38

Loaded when needed

Every tool description takes room in the context, on every request, used or not. What happens when there are hundreds?

Chapter 37 ended on a cost. The agent can use any tool that is on its list, and the list is read again for every request. Chapter 16 showed that the context is the scarcest thing an agent has. So the list competes with the conversation for the same room.

Our agent makes the problem easy to see, because everything about it is small. Its window is 112 characters. A question, its call, the result and the answer need up to 70 of them. What is left holds four entries of the list. This chapter gives it a catalogue of six.

Definitions

Progressive disclosure is giving the model a short note that something exists, and the full text only when a task needs it.

A skill is a folder of instructions for one kind of task, with a one-line description. The description is always in the context. The instructions are loaded when the task comes up.

By hand: the cost of a list

The whole catalogue, as a list:

T plus=at minus=hx times=sv mod=wu max=mr min=cl

An entry takes about 8 characters, so six take 48 with the T in front. The rest of a conversation takes up to 70 more, and the window is 112. So the list is held to four entries, which is also the most the agent ever saw in training:

T plus=at minus=hx times=sv mod=wu

The tools for max, min are gone. Nothing warns the agent or the user. And the cost is paid on every request, including the ones that need no tool at all. Now scale it:

Three ways, measured

code/ch38_skills.py asks the agent of chapter 37 the same 300 questions, spread over all six operations, in three ways.

  • Everything. The catalogue goes into the context, and what does not fit is cut off.
  • Harness picks. Before the model sees anything, the harness reads the question and lists only the tools whose description it finds there. This is the retrieval of chapter 11, applied to tools.
  • Agent asks. The first pass has an empty list. The agent of chapter 37 then says which tool it lacks: i have no tool for plus. The harness takes that as a request, loads that one entry, and asks again.
def everything(model, question):
    tools = CATALOGUE[:ROOM]                              # the rest does not fit, and is silently gone
    _, reply, read = t37.answer(model, tools, local, question)
    return reply, read, 1

def harness_picks(model, question):
    tools = [(op, name) for op, name in CATALOGUE if op in question.rstrip('?').split()]   # description found in the question
    _, reply, read = t37.answer(model, tools, local, question)
    return reply, read, 1

def agent_asks(model, question):
    _, reply, cost = t37.answer(model, [], local, question)    # first pass: no tools listed at all
    passes = 1
    if reply.startswith('i have no tool for '):           # the agent names what it lacks...
        wanted = reply[len('i have no tool for '):].rstrip('.')
        tools = [(op, name) for op, name in CATALOGUE if op == wanted]
        if tools:                                         # ...the harness loads exactly that, and asks again
            _, reply, read = t37.answer(model, tools, local, question)
            cost, passes = cost + read, 2
    return reply, cost, passes

  • Everything: 210 right, and the most to read in one pass. The 90 questions on max and min were answered i have no tool: 0 of 52 and 0 of 38 right. Both tools were in the catalogue, past the cut. And each question cost 95 characters, most of them a list it did not need.
  • Harness picks: 300 right with 74 characters. One entry in the list instead of four. It is the cheapest way, and it works here because the question contains the very word of the description.
  • Agent asks: 300 right, in two passes and 125 characters. More than either of the others. But the harness never had to understand the question. The agent said what it lacked.

The price of loading late

Loading on demand costs a pass. With six tools that pass costs more than it saves. Each entry in the list costs about 8 characters on every question, and the extra pass about 52. The two meet at about 8 tools. With 60 tools, listing everything would cost about 532 characters per question if it fitted at all, and asking would still cost 125.

So the rule is not "always load late". Load late when the catalogue is large compared with the work, and list a handful of tools that are used all the time.

At full size

  • This is how skills work. A skill is a folder with a file of instructions. Under the open format that several agents now share, loading has three levels. The name and a one-line description of every installed skill are always in the context, at a cost of about 100 tokens each. The body of instructions, which the format recommends keeping under 5,000 tokens, is read only when the model decides the task calls for it. Scripts and reference files inside the folder are read or run only if the body points to them.
  • The arithmetic is the table above. Twenty skills loaded whole could cost 100,000 tokens on every request. Their twenty descriptions cost about 2,000, plus one body when one is used.
  • The model does the choosing. It reads the descriptions and decides which body to load. So the description decides whether a skill is ever used: it has to say what the skill does and when to use it.
  • The same idea for tools. With many servers connected, a harness can keep the tool descriptions out of the context and give the model one tool that searches them. Descriptions are loaded when the search finds them.
  • And for memory and documents. A table of contents in the context and the chapters on disk; the notes of chapter 16; the retrieval of chapter 11. Each keeps a pointer in the window and the bulk outside it.

What this chapter glossed over

Our agent starts with nothing. In "agent asks" the first context has no list at all, and the agent names what it lacks. A real agent starts with one line per skill and chooses among them. That first level is not free, and ours is.

The harness looks up an exact word. Both the picking and the loading match one word. Matching a real request to a real description is a search problem, with the misses of chapter 11.

A body here is one entry. What is loaded is nine characters. A real body is pages of instructions, which is why loading it late saves so much.

A cut list fails silently. Real harnesses refuse to start, or warn, when descriptions do not fit. The silent cut is shown because it is the failure to design against.

One run. 300 questions per way, answers chosen without chance.

In short

  • A list that does not fit is cut, and nothing says so. With six tools and room for four: 210 of 300 right, and 90 answers of "no tool" for tools that existed.
  • Listing only the tool a question needs gave 300 of 300 with 74 characters to read, against 95. Letting the agent say what it lacks also gave 300, in two passes.
  • Progressive disclosure keeps a short note in the context and loads the full text when a task needs it. The cost of a catalogue then stops growing with its size.
  • A skill works this way at full size: about 100 tokens of description always, the instructions when used, the files inside it when those are needed.
  • Loading late is paid for with an extra pass. It is worth it when the catalogue is large compared with the work.

Check yourself

With the whole catalogue listed, the agent said "i have no tool for max". The tool exists. What went wrong?

The list was cut to fit the window, and the entry for max was past the cut. The agent answered truthfully about the list it was shown. The fault is in what the harness put in the context.

"Agent asks" reads more characters per question than "harness picks". When is it still the better way?

When the harness cannot tell from the request which tool is needed. The model understands the request better than a word match does, so letting it say what it needs finds tools that the harness would miss. The price is the extra pass.

A team installs 50 skills, each with 3,000 tokens of instructions. What is in the context before the first request?

Fifty descriptions, about 5,000 tokens. Loaded whole it would be 150,000. The instructions of a skill enter the context only when a task calls for it.

Why does the wording of a skill's one-line description matter so much?

It is the only part the model sees when it decides whether to load the skill. If the description does not say when to use it, the instructions behind it are never read, however good they are.

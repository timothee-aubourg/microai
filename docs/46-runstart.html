Chapter 46

What a run starts with

Each run starts with an empty context and fills it from what was saved. What goes in first, what does that cost a hundred times a day, and what keeps the saved part from rotting?

A person in a long conversation carries it in their head. An always-on agent has no head between runs. Each run, the harness builds the context from parts: the same beginning every time, what the agent knows about this person, perhaps the record of an earlier session, and the new events. This chapter weighs those parts.

Definitions

The fixed beginning of a run is what every run starts with, whatever the event: the system prompt and the tool descriptions (chapter 15).

A run can resume a session, reading back the record of an earlier one, or start a new session with only the fixed beginning, memory and the events.

Tidying memory, sometimes called dreaming, is a pass between runs, while nobody waits, that rewrites the agent's notes: replacing values that changed, removing what is no longer used, writing down patterns seen across sessions.

By hand: the same beginning, all day

The harness of chapter 15 starts every request with a system prompt of 205 characters and tool descriptions of 1,317: 1,522 characters before a single word about the task. The inbox of chapter 44 started 126 runs a day. 126 × 1,522 = 191,772, so the same text is read again nearly 200,000 characters a day.

The prefix cache of chapter 16 keeps the computed beginning so that the next request starting with the same text can skip it. A provider keeps such a cache for a few minutes after its last use. So what matters is how long the agent sleeps between runs.

Three runs in four would find the beginning in a cache that lasts five minutes. On a busy day the cache pays for itself many times. On a quiet day, with an event every hour, it would never be warm, and every run would pay the whole beginning. That is the reason to keep the fixed beginning short: tools loaded only when needed (chapter 38), instructions that say what matters and stop.

What to remember, and in what shape

Memory has its own store, outside every run. It holds only what the agent cannot look up again; for anything else, a pointer to where it is. Four kinds are common:

  • Instructions from the person, read at the start of every run.
  • Notes the agent learned: preferences, corrections, facts. Kept as an index, with details read when needed (chapters 38 and 42).
  • What was already said, so the agent does not report the same thing twice.
  • Progress on a task: what is done and what is left, the checkpoint of chapter 39.

A resumed session also carries memory, in the form of its record. But a long record has to be compacted (chapter 16), and compacting loses detail. Anything that must last belongs in the store, not in the record.

Measured: tidying the notes between runs

Chapter 42 showed that a log of every note ever written, shown in full, confused the agent. Between runs, a tidy-up pass can rewrite the notes: keep only the latest value of each name, and drop names nobody used in the last 20 sessions. The test uses the people of chapter 42, over 80 sessions each, and the agent of chapter 39.

Tidying helped, but only a little: 80 right instead of 62 with four names, and almost nothing with sixteen, where few names go unused for 20 sessions and the tidied list is nearly as long. The agent still reads several notes and mixes them, as chapter 42 found. The note asked about, alone, was right 96% to 98% of the time. Tidying keeps the store clean and small; picking what to show is what decides the answer. A full-size agent needs both.

How long the cache lives

Try this. Change how long the cache lives after its last use, and how busy the day is. Watch the share of runs that find the fixed beginning already computed.

What you should have seen. On a busy day most runs start within a few minutes of the last, so even a short-lived cache is warm three times in four. On a quiet day the same cache is almost always cold, and every run pays the full beginning: the quieter the agent, the more its fixed beginning costs per run.

Your prediction: less than half, 40%. The cache helps runs that come in clusters and does nothing for an agent that wakes rarely, which is when keeping the fixed beginning short matters most.

At full size

  • Lean beginnings, cached. Providers keep a cached prefix for minutes, some longer for a price. A beginning that never changes, placed first, gets the most from it; anything that changes, such as the date, goes after it.
  • New or resumed. A run for a new topic starts a new session; a reply in an ongoing thread resumes its session. Long sessions are compacted or replaced by a summary, and both lose detail.
  • Memory files and an index. Instructions in one file read every run; notes as an index of short lines, with longer files read only when a line points to them.
  • Tidying runs while nobody waits. Reviewing the day's sessions overnight, merging duplicates, replacing what changed and writing down patterns, is cheap because no one is waiting for it.

What this chapter glossed over

The fixed beginning is chapter 15's. Real coding agents start with much more: thousands of tokens of instructions and tool descriptions.

The cache rule is simplified: warm if the last run ended less than five minutes ago. Real caches are per prefix, shared across requests, and priced differently.

Tidying is done by rule here. At full size the tidy-up is itself a model reading sessions and deciding what to keep, with its own mistakes.

The agent was trained on up to four notes, as in chapter 42.

In short

  • Every run builds its context from parts: a fixed beginning, the person's instructions, the notes it needs, perhaps an earlier session, and the new events.
  • The fixed beginning of chapter 15's harness, read by 126 runs a day, is about 191,000 characters a day. A cache that lasts five minutes was warm for 76% of runs on a busy day, and would be cold on a quiet one.
  • Memory holds what cannot be looked up again: instructions, notes, what was already said, task progress. What must last belongs there, not in a session that will be compacted.
  • Tidying memory between runs helped a little (80 against 62 right). Showing only the note asked about helped most (377 of 384).

Check yourself

Why does a quiet agent pay more for its fixed beginning per run than a busy one?

Because its runs are far apart, so the cached beginning has expired by the next run and must be computed again. A busy agent's runs come within minutes of each other and find it warm.

The person told the agent their new address in a session last month. Where should that fact be now?

In memory, as a note that replaced the old address. Not only in the old session's record, which may have been compacted, summarised or never resumed.

Tidying removed stale notes, but the agent was still often wrong. Why?

Because it still saw several notes at once and mixed them up. Tidying makes the store correct; deciding which notes go into the context for this question is what keeps the model from being distracted.

"Store only what cannot be looked up again." Give one thing to store and one to point to.

Store: the person said "never schedule anything before 10", which exists nowhere else. Point to: the content of a document in their drive, which can be read again when needed, so memory keeps only where it is.

Chapter 48

Earning attention

An agent that works in the background can tell you everything it did, or almost nothing. Which way do you end up reading the message that matters?

When you ask an agent something and wait, you see its work as it goes. An always-on agent works while you are elsewhere, so you see only what it decides to send. Every run ends in one of three ways: it sends a message, it decides that nothing needs sending, or it asks for an approval (chapter 47). The second ending is the one that is easy to forget, and this chapter is about why it matters most.

Definitions

The outbox is where a run puts the messages it wants delivered. A small program, the dispatcher, delivers them: now, or later, together with others, or not at all.

A digest is one message that gathers many small updates, sent at a fixed time instead of one by one.

By hand: what a busy day does to a reader

This chapter measures with a small model of attention, stated in full so you can disagree with it. A message is read with probability trust × 1 / (1 + n / 6), where n is the number of messages the person got in the last 24 hours. Reading a message that mattered raises trust by 0.04; reading one that did not lowers it by 0.03.

Start with trust 0.6. With no other message that day, a message is read with probability 0.6. After 6 others it is 0.6 / 2 = 0.3. After 22 others, 0.6 / (1 + 22/6) ≈ 0.13. And each routine message that is read lowers trust a little, so tomorrow starts lower. A message that matters, sent on a day of 22 others, is read about one time in eight.

Four weeks, four ways to send

code/ch48_outbox.py simulates four weeks with this model of attention. Each day the agent has 2 things that matter (a reply arrived, a payment failed) and 20 that do not much (a task finished as planned, a small update). Trust starts at 0.6. Four ways to send, each run 50 times.

def month(way, rng):
    person = {'trust': 0.6, 'sent': [], 'opened': []}
    digest_on = way in ('digest', 'everything')
    read_important = sent = routine_read = 0
    for day in range(DAYS):
        items = sorted([(day * 24 + float(rng.uniform(8, 20)), True) for _ in range(IMPORTANT)] +
                       [(day * 24 + float(rng.uniform(8, 20)), False) for _ in range(ROUTINE)])
        pending = 0
        for t, matters in items:
            if matters:
                read_important += deliver(rng, person, t, True); sent += 1
            elif way == 'everything':
                routine_read += deliver(rng, person, t, False); sent += 1
            elif digest_on:
                pending += 1                                      # kept for the end of the day
        if pending and way != 'everything':
            routine_read += pending * deliver(rng, person, day * 24 + 20, False); sent += 1   # one digest
        if way == 'start quiet':                                  # earn attention, and give it back
            last = person['opened'][-10:]
            if len(last) == 10 and sum(last) >= 8:
                digest_on = True
            elif len(last) == 10 and sum(last) < 5:
                digest_on = False
    return {'sent': sent, 'important_read': read_important, 'important': DAYS * IMPORTANT,
            'routine_read': routine_read, 'trust': person['trust']}

A digest that is read counts all the updates in it as read.

  • Sending everything is the worst way to inform. 616 messages, and only 2 of the 56 things that mattered were read. Each routine message that was read cost trust, and the volume divided what was left. By the end the person was ignoring the agent.
  • A digest kept what matters visible. 22 items a day became 3 messages, trust stayed high, and the person read 36 of the 56 things that mattered, plus most of the routine news, because one digest read delivers twenty updates.
  • Only what matters got the most of what matters, 43 of 56, and nothing else. Whether that is best depends on whether the routine news has any value.
  • Starting quiet earned the digest after a few days of being read, and ended between the two: 39 that mattered and most of the routine updates. It is the shape advised for new agents: begin with little, and send more only once the person reads what is sent.

The numbers depend on the model of attention, which is a choice. The direction does not: every extra message divides the attention every other message gets.

A month of messages

Try this. Pick a way to send and run a month. Then change how many routine updates the agent produces a day and see which way holds up.

What you should have seen. With "everything", trust falls within days and the things that matter go unread. With a digest or only what matters, trust climbs and stays near 1. The more routine updates the agent produces, the worse "everything" gets, while the others barely change: they do not pass the volume on to the person.

At full size

  • A send tool is often enough. The agent calls it with a message; doing nothing is always an option it is told about. A formal outbox with a dispatcher helps when many runs send, to pace them, gather them and retry failed deliveries.
  • Start quiet. Builders of always-on agents advise beginning with few messages and earning attention, rather than flooding first and cutting back later.
  • Tune the volume with evaluations. Whether a message was opened, acted on or muted is a signal. A fixed set of past situations, replayed after each change (chapter 14), shows whether the agent got noisier.
  • Deciding to stay silent is a skill. The model is asked not "what did you do?" but "would the person want to know this now?". That judgement is part of what has improved in recent models.

What this chapter glossed over

Attention is a model we chose: a formula with three numbers in it. Real attention is not measured here. The direction of the result follows from any model in which more messages mean less attention for each.

"Matters" is known exactly. Here every item comes labelled. A real agent has to judge it, and its mistakes in judging are what tuning the volume is about.

A digest read counts as every item in it read. In reality people skim digests.

In short

  • An always-on agent's runs end in a message, in nothing, or in an approval. The outbox and its dispatcher decide what reaches the person, and when.
  • With a simple, stated model of attention, sending all 22 items a day led to 2 of 56 important things read in a month, and trust near zero.
  • A daily digest got 36 read, sending only what matters 43, and starting quiet then earning the digest 39, with trust near 1.
  • Every message divides the attention every other message gets. Staying silent is part of the job.

Check yourself

Why did sending everything lead to fewer important messages read than sending only those?

Because each extra message lowered the chance that any message was read that day, and every routine message read lowered trust for the days after. The important ones drowned in the rest.

A run finds nothing new. What should it send?

Nothing. "Nothing to send" is one of the three ways a run ends, and for a background agent it should be the most common one.

How would you find out, for your own agent, whether it sends too much?

Record what happens to each message: opened, acted on, ignored, muted. Replay a fixed set of past situations after each change to the agent and compare how many messages it sends and how many are acted on.

The model of attention here is made up. What, then, can the chapter claim?

The direction: if attention per message falls as messages pile up, more messages bury the important ones. The sizes, 2 against 43, belong to this model and would change with another.

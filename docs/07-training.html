Chapter 7

Watching it learn

The machine is built and its 345,504 numbers are random noise. What does learning actually look like, step by step?

Training repeats four moves, thousands of times:

  1. Pick a few random passages from the text.
  2. Run the model on them and measure the loss of chapter 1: how surprised was it by each next character?
  3. Run backward (chapter 3) to get the slope of the loss for every parameter.
  4. Move every parameter a small step against its slope.

There is no other ingredient. Nobody tells the model about words, lines, or speakers. Whatever it ends up knowing, it found because knowing it lowered the surprise.

One passage, many questions

A passage of 64 characters is not one training example. It is 64 of them. The model must predict character 2 from character 1, character 3 from characters 1 and 2, and so on. Thanks to the causal mask of chapter 5, a single pass through the model answers all of them at once without any position seeing its own answer.

From noise to Shakespeare-ish

Try this. Drag across the chart, or use the arrows, to move through training. Below it is what the model wrote at that moment. The horizontal axis is logarithmic, because most of the drama happens early.

At step 0 the output is noise: every character is as likely as any other. By step 30 the model is picking up the cheapest fact available, which characters are common, and its output drifts toward lowercase letters, spaces and line breaks. By step 100 the strings are word-shaped and the and that appear: it has learned which letters follow which. By step 300 lines start with capitals. By step 1,000 it writes speaker names in capitals followed by a colon, with short real words underneath. After that the changes are quieter: more real words, lines of verse-like length. Between steps 2,250 and 2,500 the held-out loss drops below the best count table of chapter 1.

Reading the numbers

The loss starts at 4.17. That is log 65: the freshly initialised model spreads its bets evenly over all characters. It ends near 1.5 on text it has never seen. Since the loss is an average of −log p, a loss of 1.5 means the model gives the correct next character a typical probability of e−1.5 ≈ 22%, up from 1.5% at the start.

Compare with chapter 1. The best count table reached 1.68 on unseen text and got worse when given more context. The network does better, and it does so while reading 64 characters of context, a length at which a table would be hopeless. It has the same data. The difference is that it shares what it learns between similar contexts.

The gap between the training line and the held-out dots tells you how much is memorisation. Here it stays small, because the model is tiny compared with a million characters of text: it has no room to memorise. Give a much larger model the same text and the dots would eventually turn upward while the line keeps falling. That turn is called overfitting, and the held-out loss exists to catch it.

Three additions to plain gradient descent

The loop in the code differs from chapter 3 in three small ways, each fixing a practical problem.

  • Adam. Plain descent uses one step size for every parameter. Adam keeps a running average of each parameter's recent slopes and of their typical size, and scales each parameter's step accordingly. Parameters with consistently small slopes still move. It is the default optimiser for language models.
  • A learning-rate schedule. The step size ramps up over the first 100 steps, while the slopes are still erratic, then decays smoothly so the model can settle.
  • Gradient clipping. If a batch produces an unusually large gradient, it is scaled down to a fixed maximum length. One bad batch cannot throw the model off a cliff, as in the diverging run of chapter 3.

Build it

def get_batch(source, batch_size):
    """Random windows of text. The target is the same window shifted by one character."""
    starts = rng.integers(0, len(source) - T - 1, batch_size)
    x = np.stack([source[s:s + T] for s in starts])
    y = np.stack([source[s + 1:s + T + 1] for s in starts])
    return x, y

    for p in params:
        p.grad = None
    loss.backward()                        # 2. which way should every weight move?

    gnorm = float(np.sqrt(sum(float((p.grad ** 2).sum()) for p in params)))
    clip = min(1.0, 1.0 / (gnorm + 1e-6))  # never take a wild step
    lr = float(lr_at(step))
    for i, p in enumerate(params):         # 3. move each weight a little (Adam)
        g = p.grad * clip
        m[i] = b1 * m[i] + (1 - b1) * g
        v[i] = b2 * v[i] + (1 - b2) * g * g
        mhat, vhat = m[i] / (1 - b1 ** (step + 1)), v[i] / (1 - b2 ** (step + 1))
        p.data -= lr * mhat / (np.sqrt(vhat) + eps)

The training loop. Predict, measure, backward, step.

Training a frontier model is this loop. What changes is scale: thousands of times more parameters, a large fraction of the public internet instead of one book, and warehouses of GPUs instead of a laptop. The loop above would still be recognisable.

What this chapter glossed over

The curve depends on luck. A different random initialisation or a different order of batches gives a slightly different curve and different samples. The overall shape is robust; the third decimal is not.

Lower loss is not the same as better writing. The loss rewards getting common things right. Spaces and the letter e count as much as plot. The model here learns spelling and layout long before anything like sense, and at this size it never reaches sense.

Hyperparameters were chosen by hand. Width, depth, learning rate and batch size were picked by a few quick trials to fit a browser and a coffee break. They are reasonable, not optimal.

Check yourself

Why is the loss at step 0 almost exactly 4.17 rather than some random large number?

The weights start very small, so the final scores are all close to zero and the softmax is nearly uniform over the 65 characters. Uniform guessing costs log 65 ≈ 4.17. If you ever see a much larger starting loss, the initialisation is wrong.

The training loss keeps falling but the held-out loss has started to rise. What is happening, and what do you do?

The model is memorising its training text instead of learning patterns that carry over. Stop training at the lowest held-out loss, get more data, or use a smaller model.

Why random passages rather than reading the book from start to end?

Consecutive passages resemble each other. Their gradients would push the same way for a long stretch and the model would chase the current scene. Random passages make each batch a fair small sample of the whole text.

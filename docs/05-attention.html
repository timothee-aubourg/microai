Chapter 5

Letting tokens look at each other

After chapter 4, each token's vector knows about that token and nothing else. The next character depends on everything before it. How does information travel from where it is to where it is needed?

The count table of chapter 1 had a fixed answer: look at the last few characters, always the same ones. That is rigid. To continue KING RICHARD: the model needs the newline that follows a speaker's name. To finish a word it needs the letters since the last space. What is relevant changes from position to position.

So let each position choose what to read, based on content. This is attention, and it is built from the dot product of the previous chapter.

Ask, advertise, hand over

From its vector, every token produces three new vectors, each by multiplying with its own learned matrix:

  • a query: what I am looking for;
  • a key: what I can offer;
  • a value: what I will hand over if chosen.

A token compares its query with the key of every token before it, using the dot product. A high score means "this is what I was looking for". The scores are turned into weights that are positive and add up to 1. The token then receives the weighted average of the values. That average is added to its own vector, and the token now knows something about its context.

Attention with five tokens, in two dimensions

Try this. The dark arrow is one token's query. The coloured dots are the keys of five other tokens, and each token's value is simply its colour. Swing the query toward a key and watch the output take that colour. Then pull sharpness to 0 and to 5.

At sharpness 0 the output is the plain average of all five colours: the token reads everything and learns little. At high sharpness it copies a single value. Attention can sit anywhere between a soft blend and a precise lookup, and the model learns which it needs.

Why a softmax?

The step from scores to weights is the softmax: raise e to each score, then divide by the total.

weighti = escoreiescore1 + escore2 + …

Each part of that recipe answers a need. The weights must be positive and sum to 1, so that the output is an average and keeps the same scale whether there are 5 tokens or 5,000. They must change smoothly with the scores, or gradient descent has no slope to follow. And the exponential makes the result depend on differences between scores: add 10 to every score and nothing changes. A gap of 1 between two scores always means a ratio of e ≈ 2.7 between their weights.

Why divide by a square root?

The attention formula in every implementation divides the scores by √d, where d is the number of dimensions of the queries and keys. It looks like a fussy detail. It is there because of a fact about dot products that you can check by experiment.

A dot product is a sum of d terms. If the entries of the vectors are roughly independent with a typical size of 1, each term is as likely to be positive as negative, and the sum wanders away from zero like a random walk: its typical size grows as √d. With 2 dimensions the scores are around ±1.4. With 1,024 they are around ±32. Feed scores that far apart to a softmax and one weight becomes 1 and the rest 0.

Random queries and keys, at different widths

Try this. Eight random keys, one random query. Raise the dimension and compare the two sets of bars. Without scaling, attention collapses onto one token as the vectors get wider. With scaling, it looks the same at every width.

A collapsed softmax is a problem for learning, not only for reading. Where a weight is pinned at 0 or 1 the slope is nearly flat, so the gradient has nothing to say, and at the start of training the model would be stuck with arbitrary hard choices. Dividing by √d brings the scores back to a typical size of 1 whatever the width, and leaves it to learning to sharpen them where sharpness helps.

No looking ahead

One rule is missing. During training the model sees a whole passage and must predict, at every position, the character that follows. If position 5 could attend to position 6, it would just read the answer. So before the softmax, the scores of all later positions are set to minus infinity, which gives them weight exactly 0. This causal mask is what lets one pass over 64 characters count as 64 honest predictions.

Several heads

One attention pattern per position is limiting: a token may want its previous letter and the start of the line. So the 96 dimensions are split into 4 groups of 24, and each group runs its own attention with its own queries, keys and values. These are heads. Their outputs are glued back together and mixed by one more matrix.

Attention inside the trained model

Try this. Tap a character. The shading shows how much that position reads from each earlier one, in the chosen layer and head. Positions after it are masked. Step through the heads of layer 1, then choose layer 2, head 2.

Measured over 2,500 characters of held-out text, the heads of layer 1 all do a version of the same job: they read the last few characters. Head 2 is the sharpest, with about half its weight on the character immediately before. The network has rebuilt for itself the local context that the count table of chapter 1 was given by construction. Layer 2, head 2 does something a table cannot: it sends about half its attention to the most recent line break, however far back that is. In a play script that is worth knowing, because what comes next depends on whether a line has just begun.

Build it

def attention(self, x, i, trace=None):
    B, T, d = x.shape
    h, hd = self.n_head, d // self.n_head
    split = lambda t: t.reshape(B, T, h, hd).transpose(0, 2, 1, 3)   # (B, heads, T, hd)
    q = split(x @ self.p[f'h{i}.attn.wq'])
    k = split(x @ self.p[f'h{i}.attn.wk'])
    v = split(x @ self.p[f'h{i}.attn.wv'])
    scores = (q @ k.transpose(0, 1, 3, 2)) * (1.0 / np.sqrt(hd))     # every query · every key
    future = np.triu(np.ones((T, T), dtype=bool), k=1)               # no peeking ahead
    weights = scores.masked_fill(future, -1e9).softmax(axis=-1)      # each row sums to 1
    if trace is not None:
        trace.setdefault('attn', []).append(weights.data)
    mixed = weights @ v                                              # weighted average of values
    mixed = mixed.transpose(0, 2, 1, 3).reshape(B, T, d)             # glue the heads back
    return mixed @ self.p[f'h{i}.attn.wo']

What this chapter glossed over

The √d argument has an assumption. It holds when the entries of queries and keys are roughly independent with similar spread. That is true at the start of training, and the normalisation of chapter 6 helps keep it approximately true later. It is a statement about typical size, not a guarantee.

An attention map is not an explanation. It shows where a head reads from. It does not show what was read or how it was used afterwards. Treat pretty patterns as hints.

The cost is quadratic. Every position scores every earlier position, so doubling the context quadruples the work in this step. This is the main reason long contexts are expensive, and chapter 8 shows the trick that makes generation affordable anyway.

Check yourself

In the first widget, what is the output when sharpness is 0?

All scores become 0, the softmax gives every token weight 1/5, and the output is the plain average of the five values, whatever the query is.

Our heads use 24 dimensions. What are the scores multiplied by?

1/√24 ≈ 0.204. You can see it in the code as 1.0 / np.sqrt(hd).

What would happen if you trained without the mask and then asked the model to generate?

Training loss would drop to almost zero, because every position could copy its answer from the next one. At generation time there is no next one. The model would have learned to cheat and nothing else.

Chapter 6

The whole machine

Attention moves information between positions, but a weighted average cannot compute anything new. What does the computing? And how do you stack many such steps without the signal degrading on the way?

You now have every ingredient: token vectors, attention, and a way to train. A GPT assembles them into one repeated unit, the block, and stacks it. Ours has 3 blocks. A model you download has dozens. The block is the same.

A stream that everything writes into

Picture one vector per position, 96 numbers wide, running from the bottom of the model to the top. This is the residual stream. Nothing ever replaces it. Each component reads the stream, computes something, and adds its result back in.

Each block makes two additions:

  • Attention lets positions exchange information, as in chapter 5. Tokens talk to each other.
  • The MLP then works on each position separately: it stretches the 96 numbers to 384 with one matrix, bends them through a nonlinear function, and brings them back to 96 with a second matrix. Each token thinks on its own about what it has heard.
x ← x + attention(norm(x))     x ← x + mlp(norm(x))

The nonlinear bend matters. Without it, any stack of matrices collapses into one matrix, and the model could only draw straight lines through its inputs. With it, the 384 intermediate numbers act as detectors that switch on for particular patterns, and that is where the model stores most of what it knows. Two thirds of the parameters of every block sit in its MLP.

Why add instead of replace

Suppose each block replaced the vector with its output. Then a signal passing through 30 blocks is transformed 30 times, and so is the gradient coming back. If each step shrinks it slightly, almost nothing arrives at the first block, and the early layers never learn. This was the practical obstacle to deep networks for years.

Adding fixes it with almost no machinery. The slope of x + f(x) with respect to x is 1 plus something. The "1" is a direct path: the gradient reaches every block undiminished, however deep the stack. It also changes what a block has to learn. It no longer needs to rebuild the whole representation. It only contributes a correction.

The norm in front of each component is the last piece. As blocks keep adding to the stream, its numbers could drift to any size. Layer normalisation rescales each vector to a standard spread before a component reads it, so every component sees inputs in the range it was trained on. It is also what keeps the square-root argument of chapter 5 roughly valid.

Watch a prediction take shape

Try this. Each panel reads the stream at one depth and turns it into a guess for the next character, using the output step of chapter 4. Watch the right answer rise from block to block. Then untick a block: the model still runs, because every block reads and writes the same stream. It is just worse.

Read the first panel with care. Straight after the embedding, the stream holds nothing but the current character's own row of the table, and the row most similar to it is itself. So the "guess" is simply the character just read, with full confidence. Every bit of actual prediction is added by the blocks. With the default text, the correct h gets about 40% after block 1, almost 90% after block 2, and near certainty after block 3.

Counting the parameters

With width d, each block holds four d×d matrices for attention (queries, keys, values, output) and two matrices of d×4d for the MLP: 12d² numbers in all. Add the token table, vocabulary × d.

parameters ≈ vocabulary × d + layers × 12 d²

How big is a model?

Try this. Press each preset. Then double the width and see the block parameters quadruple. Depth costs linearly; width costs quadratically.

The same line of arithmetic covers our toy and models five orders of magnitude larger. That is the sense in which you are learning the real thing. Open-weight models have refined the parts: a different normalisation, a gated MLP, positions encoded by rotation, queries sharing keys between heads. None of these change the anatomy of this chapter.

Build it

@staticmethod
def layernorm(x, g, b, eps=1e-5):
    """Rescale each token vector to mean 0, variance 1, then let the model re-stretch it."""
    xc = x - x.mean(axis=-1, keepdims=True)
    var = (xc * xc).mean(axis=-1, keepdims=True)
    return xc * (var + eps) ** -0.5 * g + b

From code/gpt.py.

def forward(self, idx, targets=None, trace=None):
    """idx: (B, T) array of token ids -> logits (B, T, vocab), and the loss if targets given."""
    B, T = idx.shape
    p = self.p
    x = p['wte'][idx] + p['wpe'][np.arange(T)]          # what the token is + where it is
    for i in range(self.n_layer):
        # tokens talk to each other...
        x = x + self.attention(self.layernorm(x, p[f'h{i}.ln1.g'], p[f'h{i}.ln1.b']), i, trace)
        # ...then each token thinks on its own
        hidden = (self.layernorm(x, p[f'h{i}.ln2.g'], p[f'h{i}.ln2.b']) @ p[f'h{i}.mlp.w1']).gelu()
        x = x + hidden @ p[f'h{i}.mlp.w2']
        if trace is not None:
            trace.setdefault('resid', []).append(x.data)
    x = self.layernorm(x, p['ln_f.g'], p['ln_f.b'])
    logits = x @ p['wte'].transpose(1, 0)               # compare with every token embedding
    if targets is None:
        return logits, None
    loss = cross_entropy(logits.reshape(B * T, self.vocab_size), targets.reshape(B * T))
    return logits, loss

The complete forward pass of a GPT. Together with the attention function of chapter 5 and the parameter list of chapter 4, this is the entire model.

What this chapter glossed over

Reading the stream halfway is an approximation. The model was trained to make its final vector readable, not the intermediate ones. The middle panels are a useful window, and they can also mislead.

What a block "does" is not well defined. "Attention communicates, the MLP computes" is a good first picture. In a trained network the work is smeared across components, and understanding it precisely is an open research field (mechanistic interpretability).

The formula is a main-terms count. It leaves out the position table and the normalisation gains. For our model it gives 338,016 against the exact 345,504.

Check yourself

How many parameters does one block of our model have, by the formula?

12 × 96² = 110,592. Three blocks give 331,776, which is 96% of the whole model.

You double the width of a model and keep the depth. What happens to its file size, roughly?

It quadruples, because the blocks scale with d². The token table only doubles, but for any model of useful size the blocks dominate.

Why does removing a block not crash the model?

Every block reads a 96-wide vector and adds a 96-wide vector. Take one out and the shapes still fit. What is lost is that block's contribution, which later blocks were trained to expect.

Chapter 6

The whole machine

Attention moves information between positions, but an average cannot compute anything new. What does the computing? And how do you stack many such steps without losing the signal on the way?

You now have every ingredient: token vectors (chapter 4), attention (chapter 5), and a way to train (chapter 3). This chapter assembles them into the model itself. It needs three more parts, and each one answers a problem you can state in a sentence.

Definitions

A transformer is a model built by repeating one unit that contains attention. A GPT is a transformer trained to predict the next token, with the causal mask of chapter 5. The model of this course is a small GPT.

The repeated unit is called a block, or a layer. Ours has 3 blocks. A model you download has dozens. The block is the same.

Part one: something that computes

Attention moves information from one position to another. What a token receives is an average of what other tokens hold. An average of vectors can only land somewhere between them: it cannot work anything out. So after each attention step, the model gives every token a moment to compute on its own.

Definitions

The MLP, short for multi-layer perceptron, is that computing step. It takes one token's vector, stretches it to a longer one with a matrix, bends every number through a fixed function, and brings it back to the original size with a second matrix.

The bend is called an activation function. The simplest one keeps positive numbers as they are and turns negative numbers into 0.

By hand: an MLP on one vector

Take the vector (1, −1). The first matrix has three columns, (1, 0), (0, 1) and (1, 1), so it stretches two numbers into three. Each new number is a dot product, as in chapter 5:

StepResult
stretch: (1, −1) with each of the three columns(1, −1, 0)
bend: negative numbers become 0(1, 0, 0)
bring back: with the columns (1, 2, 0) and (0, 1, 1)(1, 0)

The three numbers in the middle work as detectors. Each one tests the input for one pattern: the first asks "is the first entry large?", the second "is the second entry large?". The bend decides which detectors fire, and only those pass anything on. Here the second detector stayed silent. Without the bend the middle would have been (1, −1, 0), and the result (−1, −1) instead of (1, 0).

The bend is what makes this a computation. Two matrices in a row with nothing between them do no more than one matrix: multiplying a number by 2 and then by 3 is multiplying it by 6, and the same holds for tables. With the bend in between, the step can react to one pattern and ignore another.

In our model the MLP stretches the 96 numbers to 384 and brings them back to 96. The bend it uses is a smooth version of the one above, called GELU: it turns −1 into −0.16 instead of 0, and leaves 3 at 3. Smooth matters for the same reason as in the softmax: gradient descent needs slopes. Two thirds of the parameters of every block sit in its MLP, and that is where the model stores most of what it knows.

Part two: a stream that everything adds to

Now stack blocks. The obvious way is a chain: block 1 turns the vector into a new one, block 2 turns that into another, and so on. It fails for deep stacks, and the reason is in chapter 3. The slopes travel backward through every block, multiplying as they go. If each block shrinks them a little, say by a factor of 0.8, then after 30 blocks they have shrunk by 0.830 = 0.001. Almost nothing reaches the first blocks, and they never learn. This was the practical obstacle to deep models for years.

Definition

The residual stream is the vector of each position as it travels through the model. No block replaces it. Each part reads it, computes something, and adds its result to it.

By hand: two additions

A token enters a block with the vector (1.0, 2.0).

StepWhat is addedThe stream afterwards
on entry(1.0, 2.0)
attention reads the stream and adds its result(0.3, −0.1)(1.3, 1.9)
the MLP reads the stream and adds its result(−0.2, 0.4)(1.1, 2.3)

The vector that leaves the block is the one that entered plus two corrections. That is all a block does:

x ← x + attention(norm(x))     x ← x + mlp(norm(x))

Adding fixes the shrinking slopes with almost no machinery. Nudge x by a small amount and x + f(x) moves by that amount, plus whatever f adds. So its slope is 1 plus something. The "1" is a direct path: the slopes reach every block undiminished, however deep the stack. It also changes what a block has to learn. It does not have to rebuild the whole vector. It only contributes a correction.

Part three: keeping the numbers in range

The formula has a third word in it, norm. Blocks keep adding to the stream, so its numbers could drift to any size. A part that was trained on inputs of a typical size of 1 behaves badly on inputs a hundred times larger.

Definition

Layer normalisation rescales one vector so that its numbers have an average of 0 and a typical size of 1: subtract the average of its numbers from each, then divide each by their spread.

By hand

Take the vector (2, 4, 6). Its average is 4. Subtracting it gives (−2, 0, 2). The spread is the square root of the average square: the squares are 4, 0 and 4, their average is 2.67, and its square root is 1.63. Dividing gives (−1.22, 0, 1.22).

Now take (20, 40, 60), ten times larger. The same steps give (−1.22, 0, 1.22) again. The pattern is kept: which numbers are high and which are low. The size is gone. Each part of the model reads the stream through such a rescaling, so it always sees inputs in the range it was trained on. The stream itself is left as it is. It is also what keeps the square-root argument of chapter 5 roughly valid.

The whole model, from text to probabilities

Here is every step in order. Each one is something you have done by hand.

  1. Cut the text into tokens and look each one up in the embedding table (chapters 2 and 4).
  2. Add the position embedding (chapter 4). This is the start of the stream.
  3. Three times over: attention adds to the stream (chapter 5), then the MLP adds to it.
  4. Rescale the final vector once more, and take its dot product with every row of the embedding table (chapter 4). That gives one score per token.
  5. The softmax turns the scores into probabilities (chapter 5). Chapter 1's loss measures how good they are.
Definition

The scores of step 4, before the softmax, are called logits. You will meet the word in every piece of model code.

Watch a prediction take shape

Try this. The text ends in furt, and the right next character is h. Each panel reads the stream at one depth and turns it into a guess, using steps 4 and 5. Read the four panels from first to last. Then untick block 1, tick it again, and do the same with blocks 2 and 3.

What you should have seen. After the embedding, the guess is t at 100%. After block 1 the correct h has 40.2%, after block 2 it has 88.2%, and after block 3 it has 99.6%. Without block 1 the model still runs, and its final guess is wrong: e at 54.3%. Without block 2 it still says h, at 91.5%. Without block 3 it says h at 88.2%.

Read the first panel with care. Straight after the embedding, the stream holds little more than the current character's own row of the table, and the row most similar to it is itself. So the "guess" is simply the character just read. Every bit of actual prediction is added by the blocks. And removing a block does not break the model, because every block reads the same stream and adds to it. What is lost is that block's contribution. The first block's turned out to matter most here.

Counting the parameters

Call the width of the stream d; ours is 96. Each block holds four matrices of d × d for attention (queries, keys, values, and the one that mixes the heads) and two matrices of d × 4d for the MLP. That is 4d² + 8d² = 12d² numbers. Add the token table, vocabulary × d.

parameters ≈ vocabulary × d + layers × 12 d²

By hand for our model: 65 × 96 = 6,240 for the table, and 3 × 12 × 96² = 331,776 for the blocks. The sum is 338,016. The exact count is 345,504: the formula leaves out the position table and the small parameters of the normalisations.

How big is a model?

Try this. Press each preset and read the total. Then press Our model, set the width to 128, note the total, and set it to 256. Go back to Our model and double the layers from 3 to 6.

What you should have seen. Our model: 338,016. GPT-2 small: 123.5 million. The 8-billion-class model: 6.97 billion by this formula. Doubling the width from 128 to 256 takes the total from 598,144 to 2.4 million, four times as much. Doubling the layers from 3 to 6 takes it from 338,016 to 669,792, twice as much. Depth costs in proportion. Width costs with the square.

The same line of arithmetic covers our small model and models five orders of magnitude larger. That is the sense in which you are learning the real thing. Current models have refined the parts: a simpler normalisation, a gated MLP, positions encoded by rotation, heads that share keys and values. Chapter 30 goes through these. None of them changes the anatomy of this chapter.

Build it

@staticmethod
def layernorm(x, g, b, eps=1e-5):
    """Rescale each token vector to mean 0, variance 1, then let the model re-stretch it."""
    xc = x - x.mean(axis=-1, keepdims=True)
    var = (xc * xc).mean(axis=-1, keepdims=True)
    return xc * (var + eps) ** -0.5 * g + b

From code/gpt.py. The by-hand steps: subtract the average, divide by the spread. The last two names, g and b, are two small learned tensors that let the model stretch and shift the result again if that helps.

def forward(self, idx, targets=None, trace=None):
    """idx: (B, T) array of token ids -> logits (B, T, vocab), and the loss if targets given."""
    B, T = idx.shape
    p = self.p
    x = p['wte'][idx] + p['wpe'][np.arange(T)]          # what the token is + where it is
    for i in range(self.n_layer):
        # tokens talk to each other...
        x = x + self.attention(self.layernorm(x, p[f'h{i}.ln1.g'], p[f'h{i}.ln1.b']), i, trace)
        # ...then each token thinks on its own
        hidden = (self.layernorm(x, p[f'h{i}.ln2.g'], p[f'h{i}.ln2.b']) @ p[f'h{i}.mlp.w1']).gelu()
        x = x + hidden @ p[f'h{i}.mlp.w2']
        if trace is not None:
            trace.setdefault('resid', []).append(x.data)
    x = self.layernorm(x, p['ln_f.g'], p['ln_f.b'])
    logits = x @ p['wte'].transpose(1, 0)               # compare with every token embedding
    if targets is None:
        return logits, None
    loss = cross_entropy(logits.reshape(B * T, self.vocab_size), targets.reshape(B * T))
    return logits, loss

The complete forward pass of a GPT: the five steps above, in the same order. idx holds the token IDs, x is the stream, and gelu is the bend. Together with the attention function of chapter 5 and the parameter list of chapter 4, this is the entire model.

What this chapter glossed over

Reading the stream halfway is an approximation. The model was trained to make its final vector readable, not the intermediate ones. The middle panels are a useful window, and they can also mislead.

What a block "does" is not well defined. "Attention communicates, the MLP computes" is a good first picture. In a trained model the work is spread across the parts, and understanding it precisely is an open research field, called mechanistic interpretability.

The formula counts the main terms. It leaves out the position table and the parameters of the normalisations. For our model it gives 338,016 against the exact 345,504.

The by-hand bend is the simple one. It is called ReLU. Our model uses GELU, which is smooth near zero. The two do the same job.

In short

  • A GPT repeats one block. Each block makes two additions to the stream: attention, where tokens exchange information, and the MLP, where each token computes alone.
  • The MLP stretches a vector, bends it, and brings it back. The bend is what lets it react to one pattern and ignore another.
  • The residual stream is added to and never replaced. That keeps a direct path for the slopes through any number of blocks.
  • Layer normalisation rescales a vector to an average of 0 and a typical size of 1 before a part reads it.
  • In our model the right character went from 40.2% after block 1 to 99.6% after block 3.
  • Parameters ≈ vocabulary × d + layers × 12d². Ours: 338,016 by this formula, 345,504 exactly.

Check yourself

Normalise the vector (1, 3) by hand.

The average is 2, so subtracting gives (−1, 1). The squares are 1 and 1, their average is 1, and its square root is 1. The result is (−1, 1).

How many parameters does one block of our model have, by the formula?

12 × 96² = 110,592. Three blocks give 331,776, which is 96% of the whole model.

You double the width of a model and keep the depth. What happens to its file size, roughly?

It quadruples, because the blocks scale with d². The token table only doubles, but for any model of useful size the blocks dominate.

Why does removing a block not crash the model?

Every block reads a 96-wide vector and adds a 96-wide vector. Take one out and the shapes still fit. What is lost is that block's contribution, which later blocks were trained to expect.

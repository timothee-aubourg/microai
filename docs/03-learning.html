Chapter 3

Learning by rolling downhill

The model of this course will have 345,504 adjustable numbers. How do you find good values for all of them at once?

Chapter 1 ended at a wall, and with one sentence about the way past it: stop looking the answer up in a table, and compute it with a formula that contains adjustable numbers. Chapter 1 gave those numbers a name and nothing more. This chapter is where they become real, so start again from the beginning.

Definitions

A parameter, also called a weight, is one adjustable number inside a model. The two words mean the same thing in this course.

Training is the search for parameter values that make the loss of chapter 1 low. A model that has been trained is nothing more than its list of parameter values.

Here is the smallest example. Take the formula prediction = w × x. It has one parameter, w. Set w to 1 and the formula copies its input. Set it to 3 and it triples it. The formula stays the same, and the value of w decides what it does. The model built in chapters 4 to 6 is a much longer formula of the same kind, with 345,504 parameters instead of one. Nobody has built it yet. All this chapter needs from it is that number.

Trying values at random is hopeless. With 345,504 parameters, even testing just "a bit higher" and "a bit lower" for each one, in every combination, is more experiments than there are atoms in the universe.

The way out is to stop searching and start asking. For each parameter, ask one local question: if I nudge you up a hair, does the loss go up or down, and how steeply?

Definitions

The slope of the loss for a parameter is how much the loss changes when that parameter goes up by a small amount, divided by that amount. A negative slope means that raising the parameter lowers the loss.

The gradient is the list of slopes, one for every parameter.

Gradient descent is the method of this chapter: compute the gradient, move every parameter a little against its slope, repeat.

The learning rate is the number that sets how far each step goes.

each weight ← weight − learning rate × slope of the loss for that weight

By hand: one parameter, two steps

Keep the formula prediction = w × x. Give it one example: when x is 2, the right answer is 6. Measure how wrong it is by the squared distance: loss = (prediction − 6)². Start at w = 1.

wPrediction, w × 2Loss
12(2 − 6)² = 16
1.01 (nudged)2.02(2.02 − 6)² = 15.84

Raising w by 0.01 changed the loss by −0.16. The slope is −0.16 / 0.01 = −16. It is negative, so raising w helps. Take a step with a learning rate of 0.1:

w ← 1 − 0.1 × (−16) = 2.6

The loss at 2.6 is (5.2 − 6)² = 0.64, down from 16. Ask again. Nudging 2.6 to 2.61 changes the loss by about −0.03, so the slope is about −3.2. Step:

w ← 2.6 − 0.1 × (−3.2) = 2.92

The loss is now (5.84 − 6)² = 0.03. Two questions and two steps took the loss from 16 to 0.03, and w from 1 to 2.92. The value that makes the loss zero is 3. Notice that the steps got smaller without anyone deciding so: near the bottom the slope is small, and the step is the slope times the rate.

Two numbers

Now a model with two parameters: a straight line, prediction = w × x + b. Its loss is the average squared distance between the line and six data points. With one parameter the loss was a curve. With two it is a landscape: every point on the right-hand map below is one possible line, one pair (w, b), and the shading is how wrong that line is. The gradient now has two slopes, one for w and one for b.

Gradient descent on a line

Try this. Run with the learning rate at 0.05 and watch the dot slide into the valley while the line settles on the points. Reset, set the rate to 0.30 and run: it zigzags. Reset, set it to 0.33 and run. Tap the map to start somewhere else.

What you should have seen. At 0.05 the loss falls from 13.68 to 0.05 in 40 steps, and the line ends close to the points, with w = 1.97 and b = −0.91. At 0.30 the dot jumps from one side of the valley to the other, and after 40 steps the loss is still 0.45. At 0.33 each jump is larger than the last: the loss passes a million and the widget says the run has diverged.

These are two views of one process. On the left, a line moving toward the data. On the right, a dot rolling downhill. The right-hand view is the one that scales: with a million parameters you cannot draw the landscape, but "compute the slope, step against it" works unchanged.

The learning rate matters more than you might expect. Too small and training takes forever. Too large and each step lands higher up the opposite wall than where it started, and the loss grows without limit. For this little bowl the limit can be computed exactly, and it sits just above 0.30. For a real model nobody can compute it, so it is found by trial.

Getting all the slopes in one pass

There is still a cost problem. The by-hand method measures one slope by nudging one parameter and computing the loss again. Doing that for 345,504 parameters means 345,504 runs of the model for a single step.

The fix rests on one fact about slopes. A computation, however large, is built from small operations in a row: a multiplication here, an addition there. When operations follow one another, their slopes multiply.

Definitions

The chain rule: if a nudge to a changes b at a rate of 3, and a nudge to b changes c at a rate of 2, then a nudge to a changes c at a rate of 3 × 2 = 6.

The forward pass is the computation from the inputs to the loss, keeping every intermediate value.

The backward pass walks the same operations in reverse, from the loss to the parameters, multiplying slopes along the way.

Backpropagation is the name of the whole method: one forward pass, then one backward pass, gives the slope for every parameter.

By hand: forward, then backward

Take the line with w = 0.5 and b = 0.5, and one example: x = 2, right answer y = 3. Forward, one small operation at a time:

OperationValue
p = w × x0.5 × 2 = 1
s = p + b1 + 0.5 = 1.5
e = s − y1.5 − 3 = −1.5
L = e²2.25

Now backward, from the loss L. At each operation ask: if this value went up a little, how fast would L change?

ValueIts slopeWhy
e−3L = e², and the slope of a square is twice the number: 2 × −1.5
s−3e = s − y: a nudge to s moves e by the same amount
b−3s = p + b: addition passes the slope on unchanged

One walk forward and one walk back gave both slopes: −6 for w and −3 for b. Both are negative, so both parameters should go up. With a learning rate of 0.05, w becomes 0.5 − 0.05 × (−6) = 0.8 and b becomes 0.5 − 0.05 × (−3) = 0.65. The loss falls from 2.25 to 0.56.

One forward pass, one backward pass

Try this. The widget starts on the by-hand example. The blue numbers are values computed left to right. Press Backward five times and watch the raspberry slopes travel right to left. Then press Take a step and read the new loss in the box marked L.

What you should have seen. The loss starts at 2.25. The slopes appear in the order of the by-hand table: −3 at e, −3 at s, −3 for b, and last −6 for w. After the step the sliders read 0.80 and 0.65, and the loss is 0.56.

Only two rules were needed. Addition passes the incoming slope to both of its inputs unchanged. Multiplication passes it to each input scaled by the other input's value. Every operation in the model of chapters 4 to 6 has a rule of this kind, and the backward pass costs about as much as the forward pass, whether there are two parameters or two billion.

Build it

The engine below is what trains the model in this course. It needs one more word.

Definition

A tensor is a block of numbers handled as one object: a single number, a list of numbers, or a table of them.

A model's parameters are stored as a few large tensors, not as 345,504 separate variables. In the code, a Tensor holds its numbers, remembers which tensors it was computed from, and carries a small function that knows how to pass a slope back to them. The slope it has received so far is stored in grad, short for gradient.

class Tensor:
    dtype = np.float32          # switch to float64 for gradient checking

    def __init__(self, data, parents=()):
        self.data = np.asarray(data, dtype=Tensor.dtype)
        self.grad = None        # dLoss/dself, filled in by backward()
        self._parents = parents
        self._backward = None   # given dLoss/dself, pushes gradient to the parents

    def _accumulate(self, g):   # gradients from several paths ADD UP
        self.grad = g if self.grad is None else self.grad + g

    def backward(self):
        order, seen = [], set()
        def visit(t):           # topological order: parents before children
            if id(t) not in seen:
                seen.add(id(t))
                for p in t._parents:
                    visit(p)
                order.append(t)
        visit(self)
        self.grad = np.ones_like(self.data)        # dLoss/dLoss = 1
        for t in reversed(order):                  # chain rule, output -> inputs
            if t._backward is not None:
                t._backward(t.grad)            # hand the output's gradient to the op

From code/engine.py. backward() is the right-to-left walk of the widget, for any graph.

def __add__(self, other):
    other = other if isinstance(other, Tensor) else Tensor(other)
    out = Tensor(self.data + other.data, (self, other))
    def _backward(g):        # d(a+b)/da = 1, d(a+b)/db = 1
        self._accumulate(_unbroadcast(g, self.shape))
        other._accumulate(_unbroadcast(g, other.shape))
    out._backward = _backward
    return out

def __mul__(self, other):
    other = other if isinstance(other, Tensor) else Tensor(other)
    out = Tensor(self.data * other.data, (self, other))
    def _backward(g):        # d(a*b)/da = b, d(a*b)/db = a
        self._accumulate(_unbroadcast(g * other.data, self.shape))
        other._accumulate(_unbroadcast(g * self.data, other.shape))
    out._backward = _backward
    return out

def __matmul__(self, other):
    out = Tensor(self.data @ other.data, (self, other))
    def _backward(g):        # the matrix version of the product rule
        self._accumulate(_unbroadcast(g @ np.swapaxes(other.data, -1, -2), self.shape))
        if other.data.ndim == 2:   # weight matrix shared by the whole batch
            a2 = self.data.reshape(-1, self.shape[-1])
            other._accumulate(a2.T @ g.reshape(-1, g.shape[-1]))
        else:
            other._accumulate(_unbroadcast(np.swapaxes(self.data, -1, -2) @ g, other.shape))
    out._backward = _backward
    return out

The local rules for addition and multiplication, the two of the by-hand example, and for matrix multiplication, which multiplies and adds whole tables of numbers at once and is used from chapter 4 on. The file has a dozen more, all this short.

How do you know a backward rule is right? You measure the slope the slow way, by nudging one number and rerunning, and compare.

rng = np.random.default_rng(0)
model = GPT(vocab_size=11, block_size=8, n_layer=2, n_head=2, d_model=8)
x, y = rng.integers(0, 11, (3, 8)), rng.integers(0, 11, (3, 8))
_, loss = model.forward(x, y)
loss.backward()

worst = 0.0
for name, p in model.p.items():
    i = tuple(rng.integers(0, n) for n in p.shape)   # one random entry per tensor
    old, h = p.data[i], 1e-5
    p.data[i] = old + h; up = float(model.forward(x, y)[1].data)
    p.data[i] = old - h; down = float(model.forward(x, y)[1].data)
    p.data[i] = old
    numeric = (up - down) / (2 * h)                  # slope measured by brute force
    worst = max(worst, abs(numeric - p.grad[i]))
print(f'gradient check on a 2-layer GPT: worst |numeric - backprop| = {worst:.2e}')
assert worst < 1e-6

From code/ch03_gradient_descent.py. The check runs on a small copy of the model that chapter 6 builds, called GPT in the code. The two methods agree to nine decimal places.

What this chapter glossed over

The bowl is a best case. A line's loss landscape has a single valley. The landscape of a large model does not, and nothing guarantees that rolling downhill finds the lowest point. In practice, for large models, it finds points that are good enough, and why that works so reliably is still an active research question.

The slope is measured on a sample. Real training does not compute the loss on all of its text at every step. It takes a small random sample of it, called a batch, and chapter 7 does exactly that. The gradient is exact for that sample and a noisy estimate for the whole text. This is why the method is often called stochastic gradient descent: stochastic means "involving chance".

Slopes without nudging. The by-hand examples used two facts without proof: the slope of a square is twice the number, and the slope of a product is the other factor. These come from calculus, where a slope is called a derivative. Every rule in the engine is a fact of this kind, and the check above tests each one against a real nudge.

A bug worth knowing. In the first version of this engine each operation's backward function held a reference to its own output. Python could not free such cycles promptly, memory grew with every step, and training was killed at step 600. The fix was one line of design: hand the gradient to the function as an argument. Minimal code is not automatically correct code.

In short

  • A model is a formula with adjustable numbers, its parameters or weights. Training means finding values for them that make the loss low.
  • The slope of the loss for a parameter says which way to move it and how much it matters. The list of all slopes is the gradient.
  • Gradient descent repeats one step: each weight ← weight − learning rate × slope. By hand, two steps took a loss from 16 to 0.03.
  • A learning rate that is too large makes every step overshoot, and the loss grows instead of falling.
  • Backpropagation gets every slope from one forward pass and one backward pass, by multiplying slopes along the chain of operations.

Check yourself

The slope of the loss for a parameter is +4. Should the parameter go up or down, and by how much with a learning rate of 0.1?

Down. A positive slope means that raising the parameter raises the loss, so the step goes the other way: the parameter changes by −0.1 × 4 = −0.4.

In the first widget, why does a learning rate of 0.33 make the loss grow?

Across the steep direction of the valley, each step overshoots the bottom by more than the distance it started from. The error in that direction is multiplied by a factor larger than 1 at every step, so it grows without limit.

The engine adds gradients arriving at the same tensor. When does one tensor receive several?

Whenever its value is used more than once. In L = w × w, the same w enters the multiplication twice, and each use sends back a slope of w: the total is 2w. The model of chapter 6 reuses values in many places, and each use contributes a slope. The slopes add.

How many forward passes would the brute-force method need for one step of our model?

Two per parameter with the symmetric nudge used in the check: 691,008. Backpropagation needs one forward and one backward pass.

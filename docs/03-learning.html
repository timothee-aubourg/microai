Chapter 3

Learning by rolling downhill

Our model will have 345,504 adjustable numbers. How do you find good values for all of them at once?

Chapter 1 ended with a plan: replace the lookup table by a formula with adjustable numbers, called parameters or weights, and tune them so that the loss is low. Trying values at random is hopeless. With 345,504 parameters, even testing just "a bit higher" and "a bit lower" for each one, in every combination, is more experiments than there are atoms in the universe.

The way out is to stop searching and start asking. For each parameter, ask one local question: if I nudge you up a hair, does the loss go up or down, and how steeply? The answer is a number, the slope of the loss along that parameter. Collect the slopes for all parameters and you have the gradient. It points in the direction that increases the loss fastest. Step the other way.

each weight ← weight − learning rate × slope of the loss for that weight

Two numbers first

Take the smallest model that can learn anything: a straight line, prediction = w × x + b, with two parameters. Its loss is the average squared distance between the line and six data points. Two parameters means the loss is a landscape you can actually draw: every point on the right-hand map is one possible line, and the shading is how wrong that line is.

Gradient descent on a line

Try this. Run with the learning rate at 0.05 and watch the dot slide into the valley while the line settles on the points. Reset, set the rate to 0.30 and run: it zigzags. Set it to 0.33: every step overshoots further than the last. Tap the map to start somewhere else.

Two views of one process. On the left, a line wiggling toward the data. On the right, a dot rolling downhill. The right-hand view is the one that scales: with a million parameters you cannot draw the landscape, but "compute the slope, step against it" works unchanged.

The learning rate matters more than you might expect. Too small and training takes forever. Too large and each step lands higher up the opposite wall than where it started, and the loss explodes. For this little bowl the limit can be computed exactly, and it sits just above 0.30. For a real network nobody can compute it, so it is found by trial.

Getting all the slopes in one pass

There is still a cost problem. Measuring one slope by nudging one parameter requires recomputing the loss. Doing that for 345,504 parameters means 345,504 runs of the model for a single step.

The fix is the chain rule from calculus, applied with good bookkeeping. Any computation, however large, is built from small operations: an addition here, a multiplication there. Each small operation knows its own local slope. Run the computation forward and remember every intermediate value. Then walk backward from the loss, and at each operation multiply the slope that arrived by the local slope and pass it on. One backward walk delivers every slope. This is backpropagation.

One forward pass, one backward pass

Try this. The blue numbers are values computed left to right. Press Backward repeatedly and watch the raspberry slopes travel right to left. Then press Take a step and see the loss L drop.

Only two rules were needed. Addition passes the incoming slope to both of its inputs unchanged. Multiplication passes it to each input scaled by the other input's value. Every operation in a GPT has a rule of this kind, and the backward pass costs about as much as the forward pass, whether there are two parameters or two billion.

Build it

The engine below is what trains the model in this course. A Tensor holds an array of numbers, remembers which tensors it was computed from, and carries a small function that knows how to pass a gradient back to them.

class Tensor:
    dtype = np.float32          # switch to float64 for gradient checking

    def __init__(self, data, parents=()):
        self.data = np.asarray(data, dtype=Tensor.dtype)
        self.grad = None        # dLoss/dself, filled in by backward()
        self._parents = parents
        self._backward = None   # given dLoss/dself, pushes gradient to the parents

    def _accumulate(self, g):   # gradients from several paths ADD UP
        self.grad = g if self.grad is None else self.grad + g

    def backward(self):
        order, seen = [], set()
        def visit(t):           # topological order: parents before children
            if id(t) not in seen:
                seen.add(id(t))
                for p in t._parents:
                    visit(p)
                order.append(t)
        visit(self)
        self.grad = np.ones_like(self.data)        # dLoss/dLoss = 1
        for t in reversed(order):                  # chain rule, output -> inputs
            if t._backward is not None:
                t._backward(t.grad)            # hand the output's gradient to the op

From code/engine.py. backward() is the right-to-left walk of the widget, for any graph.

def __add__(self, other):
    other = other if isinstance(other, Tensor) else Tensor(other)
    out = Tensor(self.data + other.data, (self, other))
    def _backward(g):        # d(a+b)/da = 1, d(a+b)/db = 1
        self._accumulate(_unbroadcast(g, self.shape))
        other._accumulate(_unbroadcast(g, other.shape))
    out._backward = _backward
    return out

def __mul__(self, other):
    other = other if isinstance(other, Tensor) else Tensor(other)
    out = Tensor(self.data * other.data, (self, other))
    def _backward(g):        # d(a*b)/da = b, d(a*b)/db = a
        self._accumulate(_unbroadcast(g * other.data, self.shape))
        other._accumulate(_unbroadcast(g * self.data, other.shape))
    out._backward = _backward
    return out

def __matmul__(self, other):
    out = Tensor(self.data @ other.data, (self, other))
    def _backward(g):        # the matrix version of the product rule
        self._accumulate(_unbroadcast(g @ np.swapaxes(other.data, -1, -2), self.shape))
        if other.data.ndim == 2:   # weight matrix shared by the whole batch
            a2 = self.data.reshape(-1, self.shape[-1])
            other._accumulate(a2.T @ g.reshape(-1, g.shape[-1]))
        else:
            other._accumulate(_unbroadcast(np.swapaxes(self.data, -1, -2) @ g, other.shape))
    out._backward = _backward
    return out

The local rules for addition, multiplication and matrix multiplication. The file has a dozen more, all this short.

How do you know a backward rule is right? You measure the slope the slow way, by nudging one number and rerunning, and compare.

rng = np.random.default_rng(0)
model = GPT(vocab_size=11, block_size=8, n_layer=2, n_head=2, d_model=8)
x, y = rng.integers(0, 11, (3, 8)), rng.integers(0, 11, (3, 8))
_, loss = model.forward(x, y)
loss.backward()

worst = 0.0
for name, p in model.p.items():
    i = tuple(rng.integers(0, n) for n in p.shape)   # one random entry per tensor
    old, h = p.data[i], 1e-5
    p.data[i] = old + h; up = float(model.forward(x, y)[1].data)
    p.data[i] = old - h; down = float(model.forward(x, y)[1].data)
    p.data[i] = old
    numeric = (up - down) / (2 * h)                  # slope measured by brute force
    worst = max(worst, abs(numeric - p.grad[i]))
print(f'gradient check on a 2-layer GPT: worst |numeric - backprop| = {worst:.2e}')
assert worst < 1e-6

From code/ch03_gradient_descent.py. On a small GPT the two methods agree to nine decimal places.

What this chapter glossed over

The bowl is a best case. A line's loss landscape has a single valley. A network's does not, and nothing guarantees that rolling downhill finds the lowest point. In practice, for large networks, it finds points that are good enough, and why that works so reliably is still an active research question.

The slope is measured on a sample. Real training computes the loss on a small random batch of data, not all of it. The gradient is exact for that batch and a noisy estimate for the whole dataset. That is the "stochastic" in stochastic gradient descent.

A bug worth knowing. In the first version of this engine each operation's backward function held a reference to its own output. Python could not free such cycles promptly, memory grew with every step, and training was killed at step 600. The fix was one line of design: hand the gradient to the function as an argument. Minimal code is not automatically correct code.

Check yourself

In the first widget, why does a learning rate of 0.33 make the loss grow?

Across the steep direction of the valley, each step overshoots the bottom by more than the distance it started from. The error in that direction is multiplied by a factor larger than 1 at every step, so it grows without limit.

The engine adds gradients arriving at the same tensor. When does one tensor receive several?

Whenever its value is used more than once. In the GPT, the token table is used at the input and again at the output, and every residual connection uses a value twice. Each use contributes a slope, and total slopes add.

How many forward passes would the brute-force method need for one step of our model?

Two per parameter with the symmetric nudge used in the check: 691,008. Backpropagation needs one forward and one backward pass.

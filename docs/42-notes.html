Chapter 42

Memory that lasts

The model forgets everything when a session ends. What should the harness write down, and what should it put back?

A model's weights do not change while you use it, and each session starts with an empty context (chapters 11 and 16). Whatever an assistant "remembers" about you from last week, a program wrote down and put back into the context. So memory is two decisions for the harness: what to keep, and what to show the model each time.

Definitions

Long-term memory is what an agent keeps between sessions, outside the model: notes in a file or a database, put back into the context when they are needed.

A stale note is one whose fact has since changed. "n is 42", written before the person said n is now 50.

By hand: seven sessions

The agent of chapter 39 was trained to read notes: lines M n is 42 before the question, which let the question say n instead of a number. Here are seven sessions with one person:

session 1   the person says  n is 42
session 2   the person says  k is 9
session 3   the person asks  what is n times 3?
session 4   the person says  n is now 50
session 5   the person says  k is now 3
session 6   the person says  p is 18
session 7   the person asks  what is n plus 7?

Before session 7 the harness's log holds five facts, two of them out of date. If it shows every note, the context is:

M n is 42
M k is 9
M n is 50
M k is 3
M p is 18
U what is n plus 7?

The agent wrote add 28 7 and answered 35. 28 is neither the old value of n nor the new one: with five notes in view, it mixed them. If the harness keeps only the latest value of each name and shows only the name in the question, the context holds M n is 50 alone, and the agent writes add 50 7 and answers 57.

Eight people, sixty sessions each

code/ch42_memory.py simulates eight people, each over 60 sessions. In each session a person either states a fact, new or changed (four sessions in ten), or asks a question of one or two links that uses one of the names. The harness keeps a log of every fact stated, and shows notes in one of four ways. The test is repeated with 2, 4, 8 and 16 names per person. The window of the agent is 160 characters, and the question and its working need about 60 of them, so the notes get what is left.

def notes(way, log, question_names, room):
    """The note lines the harness puts before the question. `log` is every fact stated so far, in order."""
    if way == 'nothing':
        return []
    if way == 'every note':
        lines = [f'M {n} is {v}' for n, v in log]               # old values stay, next to the new ones
    else:
        latest = {}
        for n, v in log:
            latest[n] = v                                      # a new value replaces the old one
        lines = [f'M {n} is {v}' for n, v in latest.items()
                 if way == 'latest' or n in question_names]    # 'latest, picked': only what the question names
    while lines and sum(len(l) + 1 for l in lines) > room:
        lines = lines[1:]                                      # does not fit: the oldest go first
    return lines

Characters in the context at the end of each question, on average.

  • Nothing: almost never right, 3 to 7 times. Without a note the model has no way to know what n stands for, and guesses.
  • Every note: right 12% to 27% of the time, reading 122 to 125 characters, the window nearly full. Stale values sit beside new ones, and the list is cut from the oldest end to fit, which can cut the note that matters.
  • Latest: 117 of 283 with two names, falling to 40 with eight. Replacing old values removes the stale notes, but every name still comes back each time, and the list grows with the names.
  • Latest, picked: right 96% to 99% of the time, at about 70 characters, however many names a person has. The question names what it needs, and only that is shown.
  • The surprise is the two-name row. Everything fits, and still showing one unneeded note cost 160 right answers: 117 against 277. With M g is 41 and M v is 43 both in view, the agent wrote 42. The agent was trained with up to three unneeded notes. Even so, text in the context that the question does not need was a distraction.

At full size

  • Memory files. Coding agents read a file of instructions and facts about the project at the start of every session, and some let the model add to it. It is the "latest" way: the file is edited, not appended to, so old facts are replaced.
  • The model writes the notes. Here the harness wrote each note from a fixed sentence. A full-size agent decides itself what is worth remembering, often through a memory tool it can call. Deciding what to keep is then the model's job, with its own mistakes.
  • Picking needs search. Our harness picks notes by the exact name in the question. Real notes are matched to a request by meaning, with the embedding search of chapter 11.
  • Forgetting is a feature. Notes go out of date, and people ask to have things removed. A memory needs a way to correct and delete, not only to add.
  • A note is text the agent obeys. A note written from a document can carry the injected instructions of chapter 17 into every future session. What goes into memory deserves the same care as what goes into the context.

What this chapter glossed over

The notes are written by rule. A fact arrives as a fixed sentence and becomes a note exactly. Deciding what is a fact, and what a fact means, was left out.

One name per question. The agent reads one note reliably and confuses two in the same question more often, so each question uses one name. The test is of the notes, not of the reading.

The agent was trained on up to four notes. Longer lists are new to it, which is part of what "every note" and "latest" measure.

"Latest" keeps each name where it was first stated. When the list is too long it is cut from the top, so a name whose value just changed can be the first to go. Ordering the notes by their last change would keep fresh values longer; the harness here does not, and the exercise above shows the cost.

One run, no sampling.

In short

  • The model keeps nothing between sessions. Long-term memory is notes a program writes down and puts back into the context.
  • Showing every note ever written was right 12% to 27% of the time: stale notes next to new ones, and lists cut to fit.
  • Keeping only the latest value of each name, and showing only those the question names, was right 96% to 99% of the time, at about 70 characters whatever the number of names.
  • Unneeded notes hurt even when they fit: 117 right against 277 with two names.
  • A memory needs updating and forgetting, and its notes are text the agent will obey.

Act it out

Two people, index cards, a pencil · about 5 minutes

Play the seven sessions of "By hand", with the notes on index cards.

  1. One of you is the harness, who keeps the cards. The other is the agent, who turns away between sessions and may use only the cards laid on the table.
  2. The harness plays sessions 1 to 6. Each time the person states a fact, write a new card as the note line, n is 42, then k is 9, then n is 50 (the note holds the value, not the word "now"), and so on. Keep the cards in order.
  3. Session 7, every note: lay all five cards in a row and ask what is n plus 7?. Then latest, picked: put away each card that a newer one replaced, and lay only the card that names n. Ask again.

The agent knew n only from the cards, and with every note laid out it had two values for n, and only the order of the cards to say which is current. A person can use that order; the agent of this chapter, given the same five lines, mixed them and answered 35. With one card there was nothing to choose.

Check yourself

An assistant "remembers" your name from last week. Where is that memory?

Outside the model: a program stored a note and put it back into the context of this session. The model's weights did not change.

Why can keeping every note be worse than keeping only the latest one, although it holds more information?

The old values are still there, next to the new ones, and the model has to guess which is current. And the list grows until it no longer fits, so the notes that matter can be cut.

The "latest, picked" way read the fewest characters and was the most often right. What does it depend on?

On finding the right notes for the question. Here an exact name made that easy. At full size it is a search, and a note it fails to find is as good as forgotten.

A person asks the agent to forget a fact. What has to happen?

The note has to be removed from the store, and from any summary or copy made from it. Nothing in the model needs to change, because the model never held it.

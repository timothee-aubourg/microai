Chapter 21

Room to think

A model does the same amount of work for every token it writes. How can it answer a question that needs more work than that?

Look again at how a token is produced (chapter 6). The text goes once through the stack of blocks, from bottom to top, and a token comes out. Our models have two blocks. Large ones have a few dozen. Whatever the question, the number of steps between reading and answering is fixed by the depth of the stack.

Some questions need more steps than that. A person facing one of those reaches for paper. A model has something that works the same way. Each token it writes is fed back in and can be read by the next (chapter 8). So a model that writes down intermediate results has them in front of it for the rest of the answer. Its own text is its working memory.

A question that needs steps

Here is a small question of that kind. Given a row of twelve 0s and 1s, is the number of 1s odd or even?

Think of a lamp and a row of people. Each person holding a 1 presses the switch once. Is the lamp on at the end? You cannot tell from a glance at the row. No single position decides it, and changing any one of them changes the answer. You have to walk along the row.

Walking along it is easy, though. Keep one thing in mind, "odd so far" or "even so far", and update it at each position: a 1 flips it, a 0 leaves it.

By hand

Take the row 1 0 1 1 and write a mark after each position: 1 for "odd so far", 0 for "even so far".

The last mark is 1, so the answer is "odd". There are three 1s in the row, which agrees. Each line of the table needed only two things: the mark on the line above and one bit.

Definition

Thinking tokens, also called reasoning tokens, are text a model writes for itself before its answer: intermediate results that it can then read back. The row of marks above is the smallest possible example.

The first row is not a model that is sometimes wrong. It is a model that learned nothing about the question. It answered "even" to all 410 held-out rows, and 56% of those happen to be even. On rows it had trained on it got 193 of 400: it had not even memorised them. In 3,000 steps, gradient descent found no way to fit twelve flips into two blocks.

The second model wrote the correct row of marks for all 410 held-out rows. It did not memorise them either: it had never seen them. It learned the rule for one step, and the answer follows.

Why writing helps

Three things changed between the two models, and they are the three reasons this works at any size.

  1. More tokens are more work. Every token is one more pass through the stack. Twenty tokens are more than three times the computation of six.
  2. Each step became easy. "Flip or stay" needs the previous mark and one bit. A two-block model can learn that. It could not learn the whole chain at once.
  3. Results are kept where attention can find them. A mark, once written, is ordinary text in the window. The next step reads it exactly as it reads the question.

The price, and the control

Thinking is paid in tokens. The second model writes 20 or 21 tokens where the first writes 6, so each answer takes more than three times as long (chapter 18) and fills the window faster (chapter 16). At full size the proportions are larger: a model may write thousands of thinking tokens before a one-line answer.

Definition

Reasoning effort is a setting, offered by many models and services, that limits how many thinking tokens the model may write before it answers. More effort costs more time and more tokens.

A model has to be trained for that setting to work. Ours was not. It only ever saw answers that came after all twelve marks. If the harness cuts it off after eleven and demands the answer, it does not give a slightly worse answer. It writes scraps such as "en" and then starts another row of marks. The script measures 0 right out of 400.

At full size

Large models are trained on examples in which thinking comes first and the answer after, the way ours was. The chat template of chapter 15 has a place for it: Qwen3, for instance, puts the thinking between two special tokens ahead of the reply. The harness can show that part, fold it away or drop it from the conversation it sends back.

In an agent, thinking sits between the tool calls. After a tool result the model writes what the result means and what to do next, and then writes the next request. Chapter 14's traces are where you read it. When an agent picks the wrong tool, the thinking just before the call usually says why.

Build it

def held_out(bits):
    return int(bits, 2) % 10 == 0                 # one string in ten is never shown in training

def running(bits):
    """After each bit: is the number of 1s so far odd (1) or even (0)?"""
    marks, odd = '', 0
    for b in bits:
        odd ^= int(b)                             # a 1 flips it, a 0 leaves it
        marks += str(odd)
    return marks

def example(bits, steps):
    answer = 'odd' if bits.count('1') % 2 else 'even'
    thinking = f'T {running(bits)}\n' if steps else ''
    return f'U {bits}\n{thinking}A {answer}\n\n'

From code/ch21_think.py. The two formats. The only difference between the models is the line beginning with T.

def answer(run, bits, steps, budget=BITS):
    """Ask one model. Returns (its answer, everything it wrote, how many tokens it wrote).
    `budget` limits the thinking: after that many marks the answer is demanded at once."""
    cache = run.new_cache()
    def feed(text):
        for c in text:
            logits = run.step(run.stoi[c], cache)
        return logits
    def write(logits):
        c = run.chars[int(np.argmax(logits))]                        # greedy: always the likeliest character
        return c, run.step(run.stoi[c], cache)
    logits = feed('\nU ' + bits + '\n' + ('T ' if steps else 'A '))   # the prompt ends where the model takes over
    written, forced = '', 0
    if steps:
        for _ in range(budget):                                      # the thinking: one mark per bit
            c, logits = write(logits)
            written += c
        if budget < BITS:                                            # cut short: the harness asks for the answer now
            logits = feed('\nA ')
            written, forced = written + '\nA ', 3
    while not written.endswith('\n\n') and len(written) < 30 and cache['pos'] < run.block:
        c, logits = write(logits)
        written += c
    last = written.strip().split('\n')[-1]                           # the answer is the last line
    return last.replace('A ', ''), written, len(written) - forced

Asking a model: feed the prompt up to the point where it takes over, then let it write. budget cuts the thinking short.

What this chapter glossed over

The task was chosen to make the point. Counting odd or even is known to be hard for this kind of model to learn in one go and easy step by step. On most questions the gain from thinking is real and smaller.

The format of the steps matters. A first version of this experiment placed the examples anywhere in a long stream of text, and the second model failed too, at 56%. It could not find "the bit above this mark". Starting every example at the same position fixed it. Steps help only if each one is something the model can do.

Our steps were given. We wrote the row of marks for the model to imitate. Large models are trained to produce useful steps for questions nobody worked out in advance, partly by rewarding answers that turn out right. That training is beyond this course.

Written thinking is not a window into the model. The text a model writes while thinking helps it reach the answer. It is not a guaranteed account of why it gave that answer.

One run, one seed. Each model was trained once.

In short

  • A model does a fixed amount of work per token. A question that needs more than that cannot be answered in one go.
  • Thinking tokens are intermediate results the model writes and then reads back. They give it more computation, and they make each step small.
  • Two models of 103,808 weights learned the same task. Asked directly, one scored 56% on unseen rows by always saying "even". Writing one mark per bit, the other scored 400 of 400.
  • The price is tokens: 20 or 21 against 6 here. Reasoning effort is the setting that limits them, and a model must be trained to honour it.

Check yourself

Both models have the same weights count and saw the same rows. Where did the second one get its extra ability?

From the tokens it writes. Each mark is one more pass through the model, and each pass has an easy job because the previous result is written down in front of it. The ability is in the procedure, not in extra weights.

The direct model scores 56%, not 50%. Did it learn a little?

No. It answers "even" every time, and 230 of the 410 held-out rows are even. A fixed answer scores whatever share of the test set agrees with it. This is why chapter 14 says to look at the answers and not only at the score.

You set a large model's reasoning effort to its lowest level to save money, and it starts failing multi-step questions. What happened?

It has fewer tokens to work in, so fewer intermediate results fit, and questions that need many steps no longer get them. The saving and the failures come from the same cause.

Why does the thinking have to come before the answer, and not after?

A token can only read what was written before it. An answer written first is produced without the steps, in one go. An explanation added afterwards cannot change it.

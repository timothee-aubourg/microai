Chapter 31

Pictures as tokens

A language model reads tokens. A picture is not made of tokens. How does it get in?

The assistants in use today accept photographs, screenshots and scanned pages along with text. It is tempting to imagine a second machine for seeing, bolted on. There is very little of one. Inside, it is the transformer of chapters 4 to 6, unchanged. What changes is the first step, where the input is turned into vectors.

Chapter 4 turned a token into a vector by looking it up in a table: token number 17, row 17. A piece of a picture has no number to look up. But the model never needed the number. It needed the vector. So the picture is cut into small pieces, and each piece is turned into a vector of the same size as a token's, by arithmetic on its pixels.

Definitions

A patch is a small rectangle cut from a picture, treated as one unit of input.

A multimodal model accepts more than one kind of input, such as text and pictures, in the same sequence.

By hand: pixels to a vector

Take a patch of three pixels, on, off, on, written 1, 0, 1, and a matrix with one row per pixel and two columns.

PixelValueIts row of the matrix
110.2, −0.1
200.5, 0.3
31−0.4, 0.6
vector = 1 × (0.2, −0.1) + 0 × (0.5, 0.3) + 1 × (−0.4, 0.6) = (−0.2, 0.5)

Each pixel that is on adds its row. The result is a vector of two numbers, and a different pattern of pixels gives a different vector. In the model the patch has 15 pixels and the vector 64 numbers, so the matrix has 15 × 64 = 960 weights. They are trained with everything else. The table of chapter 4 is this same operation for an input with exactly one pixel on: the row is picked out whole.

The agent learns to read

code/ch31_images.py takes the agent of chapter 19 and changes what it can be asked. The first number of the sum arrives as a picture: each digit is a patch of 5 by 3 pixels. To answer, the agent has to read the digits and write them as text in its tool call, C add 23 12. Nothing tells it which pattern of pixels is which digit. It learns that from 20,000 conversations, as it learns everything else.

def picture(number, rng, noise):
    """A number as pixels: one row of 15 pixels per digit. `noise` is the chance that a pixel is flipped."""
    out = np.stack([GLYPHS[d] for d in str(number)])
    flip = rng.random(out.shape) < noise
    return np.where(flip, 1 - out, out)

def encode(text, pictures):
    """Text to token ids, and for each position its 15 pixels (zeros where there is no picture)."""
    ids = np.array([STOI[c] for c in text])
    pixels = np.zeros((len(text), 15))
    pixels[ids == STOI['#']] = np.concatenate(pictures) if pictures else 0
    return ids, pixels
def forward(self, idx, targets=None, pixels=None):
    B, T = idx.shape
    p = self.p
    x = p['wte'][idx] + p['wpe'][np.arange(T)]
    if pixels is not None:
        x = x + Tensor(pixels) @ p['patch.w']              # the only new line: pixels become part of the input
    for i in range(self.n_layer):
        x = x + self.attention(self.layernorm(x, p[f'h{i}.ln1.g'], p[f'h{i}.ln1.b']), i)
        x = x + (self.layernorm(x, p[f'h{i}.ln2.g'], p[f'h{i}.ln2.b']) @ p[f'h{i}.mlp.w1']).gelu() @ p[f'h{i}.mlp.w2']
    logits = self.layernorm(x, p['ln_f.g'], p['ln_f.b']) @ p['wte'].transpose(1, 0)
    if targets is None:
        return logits, None
    return logits, cross_entropy(logits.reshape(B * T, self.vocab_size), targets.reshape(B * T))

  • It is using the picture. With the pixels hidden it gets 5 of 300: it can only guess the number.

Draw the number

Try this. The two grids show 23, and the agent's answer is under them. Tap pixels to draw other digits. Then go back to 23 and damage one digit, a pixel at a time, until the agent misreads it.

What you should have seen. The agent writes the number you drew into its tool call, as text, and the calculator does the rest. Any one pixel of the 2 can be switched and the agent still reads 23. The 3 is less safe: of its fifteen pixels, one turns it into a 9 when switched, and that is what a 9 looks like; two others make the agent read 22. Switch two pixels of the 3 to close its left side and it is an 8: the agent calls add 28 12 and reports 40. The tool call is well formed and the arithmetic is exact. The number was misread at the start, and nothing after that can tell.

At full size

  • Patches are larger and there are many. A photograph is cut into a grid of squares, commonly 14 or 16 pixels on a side, in colour. One image becomes hundreds or thousands of vectors.
  • They take room in the context. Every patch is a position, with its place in the window (chapter 16) and its share of the KV cache (chapter 22). A page of screenshots can cost more context than a long conversation.
  • A network usually prepares the patches. Most models pass the patches through a separate network trained on images before handing its outputs to the language model. The hand-over is still a matrix that produces vectors of the right size.
  • Sound goes in the same way. A recording is cut into short slices, and each slice becomes a vector.
  • The same failure. A misread number in a screenshot leads to a confident, well-formed, wrong action. For an agent that acts on what it sees (chapter 17), reading is one more thing to check.

What this chapter glossed over

The digits are perfectly placed. Each patch holds exactly one digit, centred, at one size. Real pictures are cut on a fixed grid that ignores what is in them, and a model has to cope with a digit split across patches.

Fifteen pixels, ten shapes. This is reading in its smallest form. Recognising objects in photographs takes a far larger network and far more data, and the principle of the input is the same.

Trained from nothing, all at once. The model learned to read and to use the tool together. Full-size models usually start from a language model and an image model that were each trained separately.

Pictures go in only. Producing a picture is a different mechanism, not covered in this course.

One run. One training, one seed, 300 questions per row.

In short

  • A picture enters a language model as vectors the size of token embeddings: one per patch, made by multiplying the patch's pixels by a trained matrix.
  • After that first step the model is unchanged. Our agent gained 960 weights and one line in its forward pass.
  • It read 300 of 300 unseen numbers from clean pictures, 5 with the picture hidden, and 117 with one pixel in five flipped.
  • A misread input produces a well-formed, confident, wrong action. Patches also take room in the context, like any other position.

Check yourself

Why can a patch not simply be looked up in the embedding table, as a token is?

The table has one row per token, and there are only a few dozen tokens. A patch of 15 pixels can take 32,768 different patterns, and a photograph's patch far more. So the vector is computed from the pixels instead of being stored for each pattern.

The agent called the calculator correctly and gave a wrong answer. What happened?

It misread a digit. Everything after the reading was right: a well-formed call, an exact result, a correct sentence about the wrong number. Nothing downstream can notice, because the mistake is in the input.

With the picture hidden the agent scored 5 of 300. Why is this row in the table at all?

It shows the other rows mean something. If the agent could score well without the picture, the test would not be measuring reading. This row says that everything above it comes from the pixels.

A screenshot is cut into 1,000 patches. What does that cost, in the terms of earlier chapters?

A thousand positions of context: a thousand keys and values in every layer's cache, and that much less room for text before the window fills. Images are among the most expensive things to put in a context.
